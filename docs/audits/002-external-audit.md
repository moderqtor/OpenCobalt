# External Public Readiness Audit

SECTION 1: WHAT THIS PROJECT CLAIMS TO BE
Based on README.md (lines 3-15) and docs/PORTFOLIO_SUMMARY.md (lines 6-12), OpenCobalt claims to be a local-first AI orchestration control plane. It routes tasks to specific AI tools based on a deterministic scoring system, maintains a SQLite ledger of session events and decisions, builds context packs, and runs public safety checks before pushing. The code fully supports these claims. The CLI implementation in src/opencobalt/cli.py (lines 56-220) exposes these exact functions. The router in src/opencobalt/core/router.py (lines 65-110) implements the exact deterministic keyword scoring described. The safety scanner in src/opencobalt/core/public_safety.py (lines 79-114) correctly implements the promised hygiene checks.

SECTION 2: PUBLIC SAFETY
There is one .env.example file present (lines 1-22), but no actual .env files exist in the repository. There are no hardcoded credentials, passwords, or API keys in the source files. The test file tests/test_public_safety.py (lines 37-38) dynamically concatenates a test password string to prevent scanner false positives, which is safe. There are references to private paths like ~/cobaltos-vault and memory_store in docs/audits/000-initial-audit.md (lines 45, 140, 183) and docs/PUBLIC_SAFETY.md (lines 20-22), but these are strictly documentation context explaining why those paths are excluded. The scanner in src/opencobalt/core/public_safety.py (lines 20-25) includes them as regex patterns to block, not as active configuration. The .gitignore file (lines 20-69) correctly excludes runtime artifacts like .pytest_cache, *.db, vault_index, and memory_store. CLEAN.

SECTION 3: TEST QUALITY
The tests verify real behavior rather than just code execution. For example, tests/test_router.py (lines 4-7) test_route_summarize_is_worker_ollama specifically asserts the router returns "ollama" and "worker" for summarization tasks. Edge cases are well covered. Missing Ollama installations are handled in tests/test_models_discovery.py (lines 32-36) test_discover_models_fallback_no_ollama using mocked FileNotFoundError exceptions. Empty databases are verified in tests/test_ledger.py (lines 43-45) test_count_events_empty. Bad inputs are tested in tests/test_memory.py (lines 32-35) test_read_returns_empty_for_unknown_project. However, the project lacks CLI integration tests. There are no Typer CliRunner tests for src/opencobalt/cli.py. There are also no dedicated tests for the context compilation logic or the verify runner execution.

SECTION 4: CODE REVIEW
The module decomposition in src/opencobalt/core is highly appropriate. Data schemas are isolated in src/opencobalt/core/models.py, routing logic is isolated in src/opencobalt/core/router.py, and file system hygiene is isolated in src/opencobalt/core/public_safety.py. No obvious bugs or unhandled failure modes were found. The router correctly implements the tier classification described in docs/TOOL_ROUTING.md. In src/opencobalt/core/router.py (lines 21-52), the tools are mapped exactly to the executive, manager, and worker tiers. Furthermore, lines 89-90 correctly force the Ollama score to zero for executive tasks. The ledger schemas in src/opencobalt/core/models.py (lines 20-100) exactly match the fields promised in docs/ARCHITECTURE.md (lines 63-66). The only slightly embarrassing element is a type ignore comment in src/opencobalt/core/router.py (line 103) where the tier string is cast to a Literal type, but this is a minor typing workaround.

SECTION 5: DOCUMENTATION ACCURACY
The file docs/ARCHITECTURE.md accurately describes the code layout, data flow, and ledger tables implemented in src/opencobalt/core/models.py and src/opencobalt/core/ledger.py. The file docs/TOOL_ROUTING.md perfectly matches the implemented _TOOL_PROFILES and keywords found in src/opencobalt/core/router.py (lines 21-52). The documentation makes no unsupported claims. The project explicitly lists unimplemented features like the cost control module and UI layer under experimental sections in README.md (lines 100-105) and docs/ROADMAP.md (lines 28-36).

SECTION 6: EMPLOYER PRESENTATION
The resume bullets in docs/EMPLOYER_README_NOTES.md (lines 3-10) and docs/PORTFOLIO_SUMMARY.md (lines 22-30) are entirely accurate and verifiable. The 58 passing tests claim is backed up by the test suite size. There are no overclaims. The author specifically included a "What Not to Overclaim" section in docs/EMPLOYER_README_NOTES.md (lines 26-31) to emphasize that the router is not semantic and the project is not a production system. A technical interviewer might push back on the brittleness of pure keyword matching in src/opencobalt/core/router.py (lines 75-80) compared to basic natural language processing. They might also point out that the regex-based safety scanner in src/opencobalt/core/public_safety.py (lines 14-25) could easily miss encoded or split credentials.
